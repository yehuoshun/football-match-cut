# 提示词与数据结构

三个可直接复制的模型提示词，加两个 JSON schema。脚本负责所有本地计算，模型只做"看图打标"和"文本匹配"两件事。

---

## 1. 视觉打标提示词（S4）

输入是 `build_sheets.py` 产出的 4×4 拼图，每格左上角烧了镜头号。一次喂多张，逐张输出。

```text
你是足球转播镜头标注员。图中是一张 4x4 拼图，每格左上角有编号（S0001 形式）。
对每一格输出一行 JSON，不要解释、不要代码块、不要多余空行：

{"id":"S0001","scene":"中场倒脚|后场倒脚|边路突破|直塞|传中|角球|任意球|点球|门将扑救|射门|禁区混战|进球庆祝|球员特写|教练特写|替补席|观众席|记分牌|慢动作回放|空镜/广告|颁奖","shot":"远景|中景|特写","people":0-22,"ball":true|false,"usable":"高|中|低","note":"不超过12字"}

规则：
1. 慢动作回放一律 scene="慢动作回放"，usable="低"（除非用户明确要回放素材）
2. 画面模糊、被台标/Logo 大面积遮挡 → usable="低"
3. 观众席、空镜、广告牌 → usable="中"（可做 B-roll 过渡）
4. 看不清就填最接近的，不要空着；确实无法判断才 usable="低"
5. people 填画面里大致人数，远景按可辨认的人数量级估（0 表示无人）
```

**为什么要拼图**：一张图 16 个镜头，token 降到 1/16。代价是看不清球衣号码——判断场景/景别足够，判断"是不是某个球员"不够。

**长镜头**：若某镜头时长 > 15 秒，单独按 25%/50%/75% 抽三帧高分辨率再看一遍。

## 2. 文案拆解提示词（S5）

输入口播稿 / 分镜文案，输出"画面需求列表"。

```text
把下面的文案拆成镜头需求列表，输出 JSON 数组，不要解释：

[{"idx":1,"text":"原句","need":"画面具体要看什么","dur_min":3.0,"prio":"must|nice"}]

规则：
- 一句话里有多个动作（跑动、过人、射门）就拆成多条
- dur_min 按口播速度估：中文约 4.5 字/秒，最少 2.0 秒
- 纯情绪句、过渡句 need 填 "任意可用画面"，prio 填 "nice"
- prio="must" 只给核心动作句；其余 "nice"

文案：
<<<
{把整段文案粘在这里}
>>>
```

## 3. 匹配提示词（S6，可选）

如果不想自己写匹配逻辑，可以把需求列表 + 镜头库（只给 id/scene/shot/usable/dur）交给模型，让它输出 EDL。

```text
你有以下镜头库（来自一场足球比赛转播）和一份画面需求列表。
为每条需求挑选一个镜头，输出 EDL JSON 数组：

[{"idx":1,"shot_id":"S0312","in":"00:23:41.200","out":"00:23:48.900","reason":"一句话"}]

硬规则：
1. 镜头时长必须 >= 需求的 dur_min
2. 同一个 shot_id 默认只能用一次（除非需求列表里明确允许重复）
3. 优先 scene 语义匹配；情绪句可配特写，战术句配远景
4. 同一段文案内尽量选时间相近的镜头，避免跳戏
5. 输出时间码用 HH:MM:SS.mmm，开始时间 = 镜头 start，结束时间 = start + dur_min
镜头库：
{shots.json 精简后的数组}
需求：
{needs.json}
```

## 4. shots.json（镜头库）

```json
{
  "video": "/abs/path/match.mp4",
  "threshold": 0.25,
  "duration": 7200.0,
  "fps": 25.0,
  "shots": [
    {
      "id": "S0312",
      "start": 1421.2,
      "end": 1433.68,
      "dur": 12.48,
      "still": false,
      "scene": "边路突破",
      "shot": "远景",
      "people": 8,
      "ball": true,
      "usable": "高",
      "note": "左路内切"
    }
  ]
}
```

`still=true` 表示被 pHash 判为与前一镜头重复（慢动作/同机位），下游可跳过。

## 5. edl.json（剪辑表）

```json
[
  {
    "idx": 1,
    "src": "match.mp4",
    "in": "00:23:41.200",
    "out": "00:23:48.900",
    "dur": 7.7,
    "shot_id": "S0312",
    "scene": "边路突破",
    "text": "他从左路内切",
    "audio": "voiceover"
  }
]
```

`cut_edl.py` 只用到 `in` / `out` / `scene` / `text`，其余字段原样透传到 CSV，方便人工校对。

## 6. 事件窗口（进球片段结构）

记分牌 OCR 给出进球时刻 `T`，进攻回合按固定结构拼：

| 窗口 | 区间 | 内容 |
|---|---|---|
| A | T-30s ~ T+5s | 进攻发起 → 进球 |
| B | T+5s ~ T+20s | 慢动作回放 |
| C | T+20s ~ T+35s | 庆祝 / 观众 / 教练 |

慢放回放（B）在镜头库里的 `scene` 是"慢动作回放"、`usable="低"`，EDL 里单独标注，避免混进正片。真正要精确的只有 A 窗口的入场点——把镜头库中 A 区间内第一个"有效镜头"的 `start` 当作入场点即可，不需要逐帧找。

## 7. 质量红线

- 进球数 **以记分牌 OCR 为准**，模型的判断只作参考（越位球会被吹）
- 一个进球在正片 + 回放里出现多次，按 `±90 秒` 时间邻近合并
- 认人需求（"剪某球员"）纯视觉不可靠，远景球衣号码只有十几像素，需另做号码 OCR
